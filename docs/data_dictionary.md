## Marts models

### `mart_candidates`

Grain (repo_id, snapshot_date). THE candidate definition for training and live scoring (same SQL, mode single for live). Young, small, moving, not fork / mirror / bot-owned.

Materialized as **incremental**. Tests: 20. Built from: `int_repo_birth`, `int_repo_star_daily`, `int_young_moving_repos`, `known_bots`, `mart_snapshot_dates`, `stg_bot_actor_signals`, `stg_bot_actors`, `stg_repo_metadata`, `stg_repo_name_history`.

| Column | Type | Description |
|---|---|---|
| `repo_id` | BIGINT | GitHub repository id. The only key used to join repositories; names are display-only. |
| `snapshot_date` | DATE | Snapshot date D: the world as known at D 00:00 UTC. Only events before D are used. |
| `age_days` | BIGINT | Whole days between birth and D. |
| `stars_total_before` | INTEGER | Stars received before D. |
| `stars_14d` | INTEGER | Stars in the 14 days before D. |
| `stars_7d` | INTEGER | Stars in the 7 days before D. |
| `stars_prev_7d` | INTEGER | Stars in the 7 days before the last 7 (days D-14 to D-7). |
| `stars_1d` | INTEGER | Stars in the day before D. |
| `bucket` | SMALLINT | Hash bucket of repo_id (or actor_id) used to build the model in bounded memory (ADR-020); not meaningful downstream. |
| `birth_at` | TIMESTAMP | Estimated creation time of the repository (see int_repo_birth). |
| `birth_source` | VARCHAR | Where birth_at came from (api, create_event, public_event or first_event). |
| `repo_name_at_D` | VARCHAR | Repository name last seen before D. Display only. |

### `mart_labels`

Grain (repo_id, snapshot_date), candidates on matured snapshot dates only. Outcomes in [D, D + horizon). The relative threshold is per snapshot over all candidates.

Materialized as **table**. Tests: 13. Built from: `int_repo_star_daily`, `mart_candidates`, `mart_snapshot_dates`, `stg_trending`.

| Column | Type | Description |
|---|---|---|
| `repo_id` | BIGINT | GitHub repository id. The only key used to join repositories; names are display-only. |
| `snapshot_date` | DATE | Snapshot date D: the world as known at D 00:00 UTC. Only events before D are used. |
| `gain_30d` | INTEGER | First stars gained in [D, D + horizon_days). |
| `threshold_rel` | DOUBLE | Relative breakout threshold of the snapshot: the relative_quantile of gain_30d over its candidates, at least relative_floor_gain. |
| `breakout_rel` | BOOLEAN | True when gain_30d is at or above the relative threshold: the positive label. |
| `breakout_abs` | BOOLEAN | True when gain_30d is at least absolute_min_gain. |
| `trending_covered` | BOOLEAN | True when Trending history covers the whole horizon, so a missing Trending date is meaningful. |
| `days_to_threshold` | BIGINT | Days from D until the cumulative gain first reached the threshold; NULL when it never did. |
| `first_trending_date` | DATE | First day within the horizon the repository was on GitHub Trending, if any. |

### `mart_similar_repos`

Grain (repo_id, similar_repo_id). Co-starring cosine similarity between candidate repos and related projects (Phase 11, §11.2).

Materialized as **view**. Tests: 6. Built from: `mart_candidates`, `stg_bot_actors`, `stg_repo_metadata`, `stg_repo_name_history`, `stg_stars`.

| Column | Type | Description |
|---|---|---|
| `repo_id` | BIGINT | GitHub repository id. The only key used to join repositories; names are display-only. |
| `similar_repo_id` | BIGINT | Id of the related repository. |
| `overlap` | BIGINT | Number of stargazers both repositories share (at least 5). |
| `cosine` | DOUBLE | Co-starring cosine similarity between the two repositories, in (0, 1]. |

### `mart_snapshot_dates`

Snapshot dates D (world as known at D 00:00 UTC). weekly_history = Mondays from training.first_snapshot; single = var snapshot_date. is_label_matured = D + horizon <= latest ingested day + 1.

Materialized as **table**. Tests: 5. Built from: `stg_stars`.

| Column | Type | Description |
|---|---|---|
| `snapshot_date` | DATE | Snapshot date D: the world as known at D 00:00 UTC. Only events before D are used. |
| `is_label_matured` | BOOLEAN | True when D + horizon_days <= latest ingested day + 1, so labels can be trusted. |
| `latest_ingested_day` | DATE | Latest fully ingested day at build time. |

### `mart_suspicion`

Grain (repo_id, snapshot_date) for candidates. Robust z-score suspicion metric and 0-100 score (Phase 11, §11.1).

Materialized as **view**. Tests: 7. Built from: `feat_activity`, `feat_star_dynamics`, `feat_stargazers`, `mart_candidates`.

| Column | Type | Description |
|---|---|---|
| `repo_id` | BIGINT | GitHub repository id. The only key used to join repositories; names are display-only. |
| `snapshot_date` | DATE | Snapshot date D: the world as known at D 00:00 UTC. Only events before D are used. |
| `suspicion_score` | DOUBLE | Percentile rank of raw_score on a 0-100 scale. Display only, never a model input. |
| `suspicion_level` | VARCHAR | low (score below 90), medium (90 to 98) or high (98 and above). Describes the pattern, not intent. |
| `bucket` | SMALLINT | Hash bucket of repo_id (or actor_id) used to build the model in bounded memory (ADR-020); not meaningful downstream. |
| `s_new_accounts` | DOUBLE | Signal: share of the recent stargazers whose account was under 30 days old at the star (sg_share_account_lt_30d). |
| `s_inactive` | DOUBLE | Signal: share of the recent stargazers with no GitHub activity in the 90 days before the star (sg_share_zero_prior_activity). |
| `s_bulk` | DOUBLE | Signal: share of the recent stargazers who starred many repositories on the same day (sg_share_bulk_starrers). |
| `s_burst` | DOUBLE | Signal: largest share of the last 7 days of stars that arrived in a single hour (star_max_hour_share_7d). |
| `s_lockstep` | DECIMAL(2,1) | Reserved signal for ring detection. Constant 0 in this model; it is not part of raw_score. |
| `s_no_engagement` | DOUBLE | Signal: 1 minus the activity (forks, issue, comment and pull request events in 14 days) relative to 5% of the 14-day stars, capped at 0. |
| `raw_score` | DOUBLE | Mean of the five robust z-scores (each clipped to [0, 6] per snapshot date) of s_new_accounts, s_inactive, s_bulk, s_burst and s_no_engagement. |
